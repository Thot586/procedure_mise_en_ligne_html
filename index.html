1Créer un compte GitHub

Objectif : avoir un espace personnel gratuit où héberger vos fichiers.

  • Allez sur github.com/signup.
  • Choisissez un e-mail, un mot de passe solide et un nom d'utilisateur sobre (il apparaîtra dans l'adresse de votre site).
  • Confirmez votre e-mail avec le code reçu, puis gardez l'offre gratuite (Free).
Pas à pas détaillé
  1. Ouvrez github.com et cliquez sur Sign up (créer un compte).
  2. Saisissez votre adresse e-mail, un mot de passe long et unique (un gestionnaire de mots de passe aide), puis un nom d'utilisateur.
  3. Résolvez la vérification anti-robot, puis entrez le code à 8 chiffres reçu par e-mail.
  4. Si GitHub propose un questionnaire ou des offres payantes, ignorez-les : l'offre Free suffit.
  5. Recommandé : activez la double authentification dans Settings puis Password and authentication.
Choisir son nom d'utilisateur avec soin : votre site sera en https://NOM.github.io/…. Préférez des minuscules, sans espace, sans information personnelle sensible. Le changer plus tard casse les anciens liens.
Problèmes fréquents
  • Code non reçu : vérifiez les courriers indésirables, puis demandez un nouvel envoi.
  • Nom d'utilisateur refusé : il est déjà pris, ajoutez un chiffre ou un mot.

2Créer le premier dépôt

Un dépôt (repository) est un dossier de projet qui garde l'historique de chaque modification.

  • Bouton + en haut à droite, puis New repository.
  • Nom sans espace (ex. mon-premier-site), visibilité Public.
  • Cochez Add a README file, puis Create repository.
  • Ajoutez une page : Add file, Create new file, nommez-la index.html.
Pas à pas détaillé
  1. Cliquez sur + (en haut à droite) puis New repository.
  2. Repository name : lettres, chiffres et tirets, sans espace ni accent.
  3. Public : nécessaire pour utiliser GitHub Pages gratuitement. Tout le monde pourra voir vos fichiers.
  4. Cochez Add a README file. Laissez les autres options par défaut, puis Create repository.
  5. Sur la page du dépôt, cliquez sur Add file, puis Create new file.
  6. Nommez le fichier exactement index.html (c'est la page d'accueil). Collez-y votre contenu, par exemple le minimum ci-dessous.
  7. Cliquez sur Commit changes…, écrivez un court message (ex. « Ajout de la page d'accueil »), gardez Commit directly to the main branch, puis confirmez.
<!doctype html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <title>Ma première page</title>
</head>
<body>
  <h1>Bonjour !</h1>
  <p>Ceci est ma première page en ligne.</p>
</body>
</html>
Vocabulaire : un commit est un enregistrement daté de vos modifications, avec un message. La branche main est la version principale du projet.

3Modifier le dépôt

Changer un texte, ajouter une image ou une nouvelle page, directement dans le navigateur.

  • Ouvrez le fichier, cliquez sur l'icône crayon (Edit this file).
  • Modifiez, puis Commit changes… pour enregistrer.
  • Pour ajouter des fichiers : Add file, puis Upload files (glisser-déposer).
Pas à pas détaillé
  1. Dans la liste des fichiers du dépôt, cliquez sur index.html.
  2. Cliquez sur le crayon en haut à droite du fichier.
  3. Modifiez le texte dans l'éditeur. L'onglet Preview n'affiche pas toujours le rendu complet d'une page web : le vrai test se fait en ligne.
  4. Cliquez sur Commit changes…, ajoutez un message, confirmez.
  5. Si le site est déjà publié (étape 5), la mise à jour apparaît en ligne après 1 à 2 minutes, parfois plus.

Revenir en arrière

Ouvrez le fichier, cliquez sur History : chaque version est conservée et consultable. Rien n'est perdu tant que le dépôt existe.

Pour aller plus loin (facultatif)
  • GitHub Desktop : application graphique pour modifier sur votre ordinateur puis synchroniser.
  • Ligne de commande avec git : utile quand vous avez beaucoup de fichiers, inutile pour débuter.

4Supprimer un fichier ou le dépôt

Retirer un fichier précis, ou effacer tout le projet (et donc le site en ligne).

  • Un fichier : ouvrez-le, menu ⋯, Delete file, puis commit.
  • Tout le dépôt : Settings, tout en bas Danger Zone, Delete this repository.
Attention : supprimer le dépôt supprime aussi le site en ligne. Le lien partagé affichera une erreur 404.
Pas à pas détaillé

Supprimer un fichier

  1. Ouvrez le fichier, cliquez sur le menu ⋯ (plus d'options) puis Delete file.
  2. Ajoutez un message et confirmez avec Commit changes. Le fichier reste visible dans l'historique.

Supprimer le dépôt

  1. Dans le dépôt, onglet Settings.
  2. Faites défiler jusqu'à Danger Zone, puis Delete this repository.
  3. GitHub demande de taper le nom complet du dépôt (utilisateur/nom) pour confirmer, puis votre mot de passe ou un code.
Alternative plus douce : Archive this repository (même page Settings) rend le dépôt en lecture seule sans l'effacer. Une restauration après suppression est parfois possible pendant une durée limitée, mais ne comptez pas dessus.

5Mettre en ligne avec GitHub Pages

GitHub Pages transforme votre dépôt en site web gratuit, avec une adresse à partager.

  • Settings, puis Pages dans le menu de gauche.
  • Source : Deploy from a branch, branche main, dossier / (root), puis Save.
  • Attendez 1 à 10 minutes. L'adresse est https://NOM.github.io/NOM-DU-DEPOT/.
Pas à pas détaillé
  1. Vérifiez que le dépôt est Public et contient un fichier index.html à la racine.
  2. Onglet Settings, puis Pages (section Code and automation).
  3. Sous Build and deployment, Source : Deploy from a branch.
  4. Branch : main et dossier / (root), puis Save.
  5. Rechargez la page de réglages après quelques minutes : un bandeau indique l'adresse publiée. Vous pouvez suivre le déploiement dans l'onglet Actions.
  6. Cochez Enforce HTTPS si l'option est proposée (connexion sécurisée).

Ça ne marche pas ? (erreur 404, page blanche)
  • Patientez : la première publication peut prendre plusieurs minutes.
  • Le fichier doit s'appeler index.html, tout en minuscules, à la racine.
  • Les noms de fichiers sont sensibles à la casse : Image.PNG n'est pas image.png.
  • Dans une page, utilisez des chemins relatifs (image.png) plutôt que /image.png : sur un site de projet, le slash initial pointe vers la racine du domaine, pas vers votre dépôt.
  • Dépôt privé avec offre gratuite : Pages n'est pas disponible, passez le dépôt en public.

6Apparaître dans les moteurs de recherche

Le référencement n'est jamais instantané ni garanti : comptez de quelques jours à quelques semaines.

  • Soignez la page : un <title> clair, une meta description, des titres h1, h2.
  • Inscrivez le site dans Google Search Console, vérifiez-en la propriété, demandez l'indexation.
  • Faites de même dans Bing Webmaster Tools (import possible depuis Google).
Préparer la page (avant de s'inscrire)

Dans le <head> de votre index.html :

<html lang="fr">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Titre précis de la page (moins de 60 caractères)</title>
  <meta name="description" content="Résumé de la page en une ou deux phrases.">
</head>
  • Un seul h1 par page, qui dit de quoi parle la page.
  • Du vrai texte (pas seulement des images), un texte alternatif (alt) sur chaque image.
  • Des liens vers votre page depuis d'autres sites ou réseaux sociaux : cela aide les moteurs à la découvrir.
Google Search Console, pas à pas
  1. Ouvrez Google Search Console avec un compte Google.
  2. Choisissez Préfixe de l'URL (le type « Domaine » n'est pas possible sur github.io, qui n'est pas à vous) et saisissez l'adresse complète de votre site, avec https:// et la barre finale.
  3. Vérification de propriété : choisissez Balise HTML. Google fournit une ligne <meta name="google-site-verification" …> à coller dans le <head> de votre index.html (étape 3), puis cliquez sur Valider.
  4. Dans la barre du haut, collez l'adresse de votre page (Inspection de l'URL), puis Demander une indexation.
  5. Facultatif : ajoutez un plan de site (sitemap.xml) dans le menu Sitemaps.

Exemple minimal de plan de site

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://NOM.github.io/mon-premier-site/</loc>
  </url>
</urlset>

Enregistrez-le sous sitemap.xml à la racine du dépôt.

Limite à connaître : pour un site de projet (NOM.github.io/depot/), le fichier robots.txt doit se trouver à la racine du domaine, que vous ne contrôlez pas. Il n'est pas indispensable pour être indexé.
Bing et les autres moteurs
  • Bing Webmaster Tools : ajoutez votre site, ou importez-le depuis Google Search Console.
  • Plusieurs moteurs alternatifs reprennent l'index de Bing : l'inscription Bing a donc un effet indirect.
Vérifier si la page est indexée
  • Dans Google, tapez site:NOM.github.io/mon-premier-site. Aucun résultat signifie « pas encore indexée » ou « non indexée ».
  • Dans Search Console, le rapport Pages indique l'état et les raisons d'une éventuelle exclusion.
  • Une page indexée n'apparaît pas forcément en haut des résultats : le classement dépend de nombreux facteurs.

7Toutes les infos utiles

À lire une fois, pour éviter les mauvaises surprises.

  • GitHub Pages est gratuit pour un dépôt public, mais il ne sert que des pages statiques (pas de base de données ni de code serveur).
  • Tout ce qui est dans un dépôt public est lisible par tous : jamais de mot de passe, de clé ni de donnée personnelle.
Coût, limites et usages permis
  • Gratuit avec l'offre Free pour les dépôts publics. Les dépôts privés avec Pages demandent une offre payante.
  • Limites indicatives publiées par GitHub : site de 1 Go au plus, environ 100 Go de trafic par mois, environ 10 publications par heure. Vérifiez les valeurs actuelles dans la documentation officielle.
  • Pages n'est pas prévu pour héberger une boutique en ligne ou un service commercial : consultez les conditions d'utilisation.
Sécurité et vie privée
  • Activez la double authentification sur votre compte.
  • Ne publiez jamais de mot de passe, de clé d'accès ou de données de patients, d'élèves ou de clients.
  • Même si une donnée est supprimée d'un fichier, elle reste dans l'historique des versions tant que le dépôt existe.
  • Votre nom d'utilisateur étant dans l'adresse, il est public.
Utiliser votre propre nom de domaine (facultatif)
  1. Achetez un nom de domaine chez un bureau d'enregistrement (payant, environ une dizaine d'euros par an en général).
  2. Dans Settings, Pages, renseignez Custom domain.
  3. Chez votre bureau d'enregistrement, ajoutez les enregistrements DNS indiqués dans la documentation GitHub.
  4. Patientez (de quelques minutes à 24 h), puis cochez Enforce HTTPS.

Glossaire
  • Dépôt (repository) : dossier de projet suivi par GitHub, avec son historique.
  • Commit : enregistrement d'un ensemble de modifications, accompagné d'un message.
  • Branche : version parallèle du projet. main est la principale.
  • HTML (HyperText Markup Language) : langage qui décrit le contenu d'une page web.
  • URL (Uniform Resource Locator) : adresse d'une page web.
  • HTTPS : connexion chiffrée entre le visiteur et le site (le cadenas du navigateur).
  • DNS : annuaire qui associe un nom de domaine à un serveur.
  • Indexation : enregistrement d'une page dans la base d'un moteur de recherche.
  • Page statique : page identique pour tous les visiteurs, sans traitement côté serveur.
